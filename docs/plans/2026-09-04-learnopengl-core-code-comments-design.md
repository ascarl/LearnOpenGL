# LearnOpenGL 核心代码中文注释设计

## 背景与目标

LearnOpenGL 仓库中的示例已经包含部分英文分段注释，但学习者仍需在入口程序、公共封装和 Shader 之间来回推断数据流。本次工作为项目自有核心代码补充简体中文教学注释，让读者能够快速回答三个问题：当前示例学习什么、数据如何经过渲染管线、关键 OpenGL 状态或公式为什么这样设置。

本次修改只增加或整理注释，不改变程序行为、接口、资源路径、Shader 表达式或构建配置。

## 范围

覆盖以下项目自有文件：

- `src/` 下的演示入口和辅助 `.cpp`、`.c`、`.h` 文件；
- `includes/learnopengl/` 下的公共辅助头文件；
- `src/` 下的 `.vs`、`.fs`、`.gs`、`.tcs`、`.tes`、`.cs` Shader 文件。

明确排除：

- `src/glad.c`：GLAD 生成代码；
- `src/stb_image.cpp`：stb_image 第三方实现；
- 构建产物、资源文件、第三方库和系统生成文件；
- 没有教学价值的逐行语法翻译。

## 注释层级

### 文件级说明

每个目标文件都应有简洁的中文文件头。演示程序说明课程目标、主要渲染阶段、关联 Shader/资源和交互方式；公共辅助代码说明职责、资源所有权和典型调用关系；Shader 说明所属阶段、输入、输出、关键 uniform 与核心算法。

文件头应基于该文件的实际实现编写，不使用只有文件名不同的空泛模板。相邻练习或答案文件应指出它相对基础示例增加或改变的概念。

### 模块级说明

在 C/C++ 的关键逻辑边界增加中文说明，包括：

- GLFW/OpenGL 上下文初始化；
- 顶点、索引、纹理、Uniform Buffer、Framebuffer 等 GPU 资源准备；
- Shader 创建、参数绑定和坐标空间转换；
- 每帧更新、状态切换、绘制顺序与多 Pass 数据流；
- 输入处理、相机更新、时间步进和资源释放；
- 阴影、HDR、Bloom、延迟渲染、SSAO、PBR、骨骼动画等算法阶段。

Shader 注释重点解释坐标空间、插值数据、采样含义、光照项、阈值或权重公式以及输出目标。简单赋值和显而易见的控制结构不逐行注释。

### 符号级说明

只为语义不明显的结构、函数、状态变量和数学参数补充说明。注释解释“为什么”和“数据属于哪个空间/阶段”，避免重复变量名已经表达的“是什么”。

## 写作规范

- 统一使用简体中文，保留 OpenGL、Shader、Framebuffer、BRDF 等常用术语；首次出现容易混淆的术语时补充中文含义。
- 保留准确且有价值的原英文注释；中文说明与其重复时进行合并，避免双语内容连续堆叠。
- 使用原创、简洁的表述，不复制教程原文的大段内容。
- 注释紧邻其解释的代码，避免跨越过长代码块。
- 不把平台限制写成算法本身的限制；只在确实请求 OpenGL 4.2+ 等版本的示例中标明 macOS 系统 OpenGL 兼容性。
- 不对代码进行顺手重构、格式化或变量重命名，保证差异仅限注释。

## 实施顺序

按课程依赖分批处理和审查：

1. `1.getting_started`：窗口、管线、Shader、纹理、变换、坐标系、相机；
2. `2.lighting` 与 `3.model_loading`：光照模型和模型数据；
3. `4.advanced_opengl`：深度、模板、混合、Framebuffer、Cubemap、UBO、实例化和 MSAA；
4. `5.advanced_lighting` 与 `6.pbr`：高级光照、多 Pass 和 PBR；
5. `7.in_practice`：调试、文字与 2D 游戏；
6. `8.guest`：场景、动画、地形、CSM、Compute Shader 等专题；
7. `includes/learnopengl`：结合所有调用点完善公共封装说明。

每一批先识别该示例新增的教学点，再补文件级与关键路径注释。公共封装放在最后，可避免脱离真实调用场景编写错误说明。

## 验收与验证

完成后执行以下检查：

- 文件清单检查：所有范围内文件都有文件级中文说明，排除文件保持不变；
- 差异检查：`git diff --check` 无空白错误，差异中不存在非注释代码修改；
- 构建检查：重新配置 Debug 构建并全量编译 C/C++ 目标；
- Shader 检查：确认注释使用目标语言支持的 `//` 形式，并运行覆盖顶点、片段、几何、细分和计算阶段的代表性示例；
- 平台边界：在 macOS 上明确区分“成功编译”和“系统 OpenGL 版本不足而无法运行”；
- 人工抽查：每章至少抽查一个基础示例和一个复杂示例，确认注释与真实调用和数据流一致。

验收结果应分别报告已验证的构建、可运行示例、受 macOS OpenGL 4.1 限制的示例，以及任何未能执行的运行时验证。
